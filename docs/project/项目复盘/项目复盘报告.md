## 1. 项目背景与核心痛点

### 1.1 背景
企业 AI 应用从「单轮问答」走向「多步骤任务执行 + 知识沉淀」。当前主流 LLM 应用平台普遍停留在"通用助手 + 静态 RAG"，存在三大痛点：

1. **知识沉淀难**：业务侧经验散落 Chat / 文档 / 聊天，沉淀靠人工事后整理，遗忘率 > 70%
2. **复杂任务执行效率低**：单 Agents 难胜任需要拆解 → 检索 → 生成 → 审核多维度的任务
3. **复用率低**：相同子类型的任务每次重做，AI 不能自动复用历史交付的"经验"

### 1.2 目标
构建"执行即沉淀"的多 Agent 协同工作台，让一次任务自动产出成果 + 可被检索复用的结构化知识，形成"越用越聪明"的正向闭环。

## 4. 核心模块实现

### 4.1 用户与团队空间
- JWT 双令牌（access + refresh），refresh 单次轮换 + 黑名单
- RBAC 三级：super_admin / space_admin / member；中间件校验
- 所有业务表强制 `space_id` 隔离

**关键设计**：refresh token 表 `refresh_tokens` 以 jti 唯一，服务端校验"未撤销 + 未过期"再颁发新对，避免 token 重放。

### 4.2 任务执行中心
- 任务状态机 `pending → running → succeeded/failed/interrupted`，运行后可 `resume`
- 异步执行：`engine.submit` 立即返回 execution_id；后续进度走 SSE 流推
- 控制指令：写 Redis `task:run:{id}:control=stop`，LangGraph 节点边检查
- 链路回溯：`agent_steps` 表记录每节点 input/output/tools/tokens/duration，可一键追溯

### 4.3 多 Agent 编排引擎
- GraphState 全局状态机：subtasks / materials / drafts / review_round / status
- 节点：decompose → retrieve → generate → review（条件分支循环，最多 REVIEW_MAX_ROUNDS=2）
- 监控：每节点 emit SSE 事件写 Redis 队列；前端按 subtask_id 分流式累积
- 续跑：基于 Redis checkpointer 持久化 GraphState，恢复时加载最近 checkpoint

### 4.4 知识沉淀系统
- 触发：succeeded 立即触发；failed 但执行时长 ≥60s 且 ≥5 步触发"踩坑"提取
- 四类抽取：experience / template / knowledge / pitfall
- 清洗：哈希去重、LLM 自动摘要 + 自动打标、清理隐私
- 入库：400 字 + 40 字 overlap 语义分片 + embedding + Chroma 写入
- 复用闭环：下次相似任务 ResearchRetriever 优先召回相同空间历史知识 + usage_count 累计 + 时间衰减

### 4.5 检索召回服务
三路融合：`semantic + keyword + scene + quality + time_decay`
权重 0.45 / 0.20 / 0.15 / 0.10 / 0.10；默认 quality_score<0.3 不进入默认召回。

### 4.6 工程化与部署
- Docker Compose 5 服务编排（MySQL / Redis / Chroma / backend / ai + frontend）
- Nginx SSE 关键配置 `proxy_buffering off` + 响应头 `X-Accel-Buffering: no`
- Alembic 迁移、单测覆盖关键模块（约 7 类）

### 4.7 MetaGPT 模式落地
- **Role**：BaseRole / BaseAgent，`_think/_act/_observe` 三段式
- **Team**：`hire/disband/run/excute_task`
- **Environment**：消息发布/订阅，按 watch 列表过滤
- **Memory**：长期 + 工作记忆 + Chroma 向量检索
- **Plan/Task**：拓扑排序 + 依赖管理 + current_task
- **Tool**：ToolRegistry + `@register_tool` + ToolRecommender（GOAL-06 落地）
- **Skill**：SkillManager + config.json + skprompt.txt（GOAL-07 落地）

## 5. 核心问题与解决方案

### 5.1 多 Agent 协同稳定性
- **问题**：循环死锁 / 状态错乱 / checkpointer 与业务态不一致
- **方案**：所有 Agent 间通信走 Environment 消息队列；LangGraph RedisSaver 自研以 HSETNX 原子写
- **量化**：并发 20 以下无状态错乱；单任务失败 5s 内可 resume

### 5.2 SSE 流式输出的一致性
- **问题**：Nginx 默认缓冲导致 token 一坨；浏览器断线；前端时间轴与后端节奏不一致
- **方案**：Nginx `proxy_buffering off` + `proxy_read_timeout 0` + 响应头 `X-Accel-Buffering: no`；前端 fetch+ReadableStream 解析事件块；5s 心跳保活
- **验收目标（未实测）**：端到端 token 延迟 < 500ms；断线续传由 SSE 自动化测试覆盖

### 5.3 知识沉淀质量保障
- **问题**：错误内容 / 半成品 / 重复混入检索
- **方案**：仅 succeeded 任务自动沉淀；初始 quality_score=0.5；usage_count 累计 + 用户反馈更新；默认 < 0.3 不召回
- **验收目标（未实测）**：高质知识占比 ≥ 80%；劣质内容自动衰减

### 5.4 返工不破坏既有内容
- **问题**：返工轮 LLM 重写全部内容
- **方案**：Reviewer 仅针对 issue 返回 targeted edit；Generator 仅重写命中 subtask_id
- **验收目标（未实测）**：返工后整体差异 < 30%，目标章节修正率 100%
