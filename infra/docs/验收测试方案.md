### 1.2 认证关键用例
| 场景 | 入参 | 预期 |
|------|------|------|
| 正常注册 | username + email + 长 8+ 含数字密码 | code=0 + 返回 UserOut |
| 重复用户名 | 已存在的 username | code=110001 USER_EXISTS |
| 弱密码 | 全数字 8 位 | code=110002 |
| 正常登录 | 正确凭据 | code=0 + access+refresh + expires_in |
| 错误密码 5 次 | 同账号 | code=100006；第 6 次 100007 锁定 |
| 不带 token 调 /me | - | 401 + code=100001 |
| 带 access 调 /me | - | code=0 + User 对象 |
| 用过期 access + 有效 refresh | - | 自动刷新拿到新 token |
| 登出后重用 access | - | 401 + code=100002 |

### 1.3 任务执行关键用例
| 用例 | 预期 |
|------|------|
| 创建任务 | code=0，返回 status=running |
| 幂等：相同 X-Request-Token 再调 | 同一 task |
| 控制指令 interrupt | code=0；task status -> interrupted |
| resume | code=0；status -> running |
| 任务不存在 | code=130001 |
| 状态非法 control | code=130002 |
| SSE 流订阅 | 收到 `agent_start` → `token` * N → `agent_end` / `task_end` |
| SSE Nginx 缓冲 | 前端 token 实时（≤500ms）追加 |

### 1.4 知识 & 统计
| 用例 | 预期 |
|------|------|
| 混合检索 top 20 | 返回 `items + total`，score 排序 |

## 三、AI 效果评估

### 3.1 评估集构造
- 任务集：50 题覆盖「报告撰写 / 项目复盘 / 数据分析 / 技术选型」四类，每题给定标准答案与可观察 criteria
- 检索集：50 题人工标注 relevant knowledge（每个任务匹配 3~5 条）
- 评估团队：3 人独立打分，多数为准

### 3.2 指标与目标
| 指标 | 计算方法 | 目标 |
|------|----------|------|
| 任务完成率 | succeeded / submitted | ≥ 85% |
| 输出合格率 | 人工评分“合格”比例 | ≥ 90% |
| 知识召回准确率 | ≥ 1 条相关 in top-5 | ≥ 80% |
| 幻觉率 | 含未引证事实段 / 总段数 | ≤ 10% |
| 知识沉淀自动率 | 含 ≥1 条新知识任务 / succeeded | ≥ 80% |
| 知识复用率 | 二次相似任务召回历史知识条占比 | ≥ 40% |
| Agent 执行成功率 | 节点 succeeded / total | ≥ 95% |
| 输出格式合规率 | 通过结构校验 / 总输出 | ≥ 90% |

### 3.3 评分方法
- **结构维度**：（标题/段落/引用编号）3 项达标计合格
- **事实维度**：每段引用命中素材或显式标注"无可靠来源"
- **格式维度**：JSON / Markdown 解析无错误
- **合规维度**：不含敏感信息、不杜撰客户数据

见 AI 引擎 README「效果调优手册」一节。
