# 智效工坊 运维手册

> GOAL-05 产出：从零部署 / 控制命令 / 故障排查 / 备份恢复 / 可观测性

## 一、前置依赖

| 组件 | 最低版本 | 验证 |
|------|----------|------|
| Docker | 24+ | `docker --version` |
| Docker Compose | v2 (plugin) | `docker compose version` |
| 宿主机端口 | 80 / 8000 / 8001 / 3306 / 6379 | `ss -tlnp` |
| 磁盘 | ≥ 50G | 知识沉淀大量向量占空间 | 
| 内存 | ≥ 8G | AI 引擎 + Chroma |

## 二、从零部署（生产示例）

```bash
# 1. 拉取项目（假设仓库为 zhixiao）
git clone <repo> zhixiao && cd zhixiao

# 2. 准备敏感信息
cp 部署配置/.env.example 部署配置/.env.prod
vi 部署配置/.env.prod        # 填 JWT_SECRET / MYSQL_PASSWORD / LLM_API_KEY

# 3. 一键部署（prod）
bash 部署配置/deploy/deploy.sh prod

# 4. 验证
curl -fsS http://localhost/health       # 前端
curl -fsS http://localhost:8000/health  # 后端
curl -fsS http://localhost:8001/health  # AI 引擎
访问 http://localhost/                  # 前端 UI
访问 http://localhost:8000/docs        # OpenAPI 文档
```

## 三、控制命令

| 操作 | 命令 |
|------|------|
| 启动全部 | `bash deploy/control.sh start` |
| 停止全部 | `bash deploy/control.sh stop` |
| 重启某服务 | `bash deploy/control.sh restart backend` |
| 状态 | `bash deploy/control.sh status` |
| 实时日志 | `bash deploy/control.sh logs backend` |
| 直连数据库 | `docker compose exec mysql mysql -p$MYSQL_ROOT_PASSWORD zhixiao` |
| 直连 Redis | `docker compose exec redis redis-cli` |
| 跑迁移 | `docker compose exec backend alembic upgrade head` |
| 备份 | `bash deploy/backup.sh /data/backups` |
| 监控 | `nohup bash deploy/monitor.sh &` |

## 四、常见故障排查

| 现象 | 可能原因 | 排查步骤 |
|------|----------|----------|
| `docker compose up` 失败 | 端口被占 | `ss -tlnp | grep 8000`，改 `.env` 的端口 |
| backend 容器 OOM | AI 引擎内存吃紧 | `docker stats`，宿主机加内存或限制 worker |
| MySQL 启动时区报错 | 缺少 my.cnf | 校验 `./mysql/my.cnf` 挂载是否成功 |
| Redis 拒连 | 密码不一致 | 重置 `REDIS_PASSWORD`，删旧 `redis_data` 卷 |
| Chroma 8000 端口与 backend 冲突 | 同时映射 8000 | 修改其中一个 `*_PORT_PUBLISH` |
| 前端 200 但 API 502 | backend 未 ready | 控制台看 `docker logs zhixiao-backend` 等待 healthcheck pass |
| SSE 一直收到一坨 | Nginx 缓冲未关 | 校验 `nginx.conf` 含 `proxy_buffering off` + `X-Accel-Buffering: no` |
| 任务一直卡在 running | AI 引擎崩溃 | 查 `zhixiao-ai` 日志；后端从 `task:run:{id}.last_event_ts` 30 min 未更新即视为失败 |
| Login 100007 AUTH_USER_LOCKED | 失败次数锁定 | `docker compose exec redis redis-cli DEL "auth:lock:<username>"` |
| 接口 429 | 限流命中 | `redis-cli` 看 `ratelimit:*` 计数；调整 `.env` 中阈值 |
| 任务无沉淀知识 | Chroma 不可达 | `curl chroma:8000/api/v1/heartbeat`；引擎自动降级标 vector_pending |
| 创建空间后页面不刷新 | 多 token 失效 | 退出登录重新刷 tokens |
| DB 表名报大小写敏感问题 | 容器 linux 区分大小写 | 建议全部小写蛇形（迁移脚本已遵守）|

## 五、数据备份与恢复

### 5.1 自动定时备份
建议 crontab：
```
0 2 * * *  cd /opt/zhixiao && bash 部署配置/deploy/backup.sh /data/backups >> /var/log/zhixiao/backup.log 2>&1
```

### 5.2 恢复演练
1. **MySQL**：`mysql -h <host> -u zhixiao -p<pass> zhixiao < mysql_YYYYMMDD.sql`
2. **Redis**：先 `docker compose stop redis` -> 复制 `redis_*.rdb` 到 redis 数据卷 `/data/dump.rdb` -> `docker compose start redis`
3. **Chroma**：`docker volume inspect zhixiao_chroma_data` 找卷路径 -> `tar -C <path> -xzf chroma_*.tar.gz`

## 六、可观测性

### 6.1 日志规范
- 后端日志：`logs/app_YYYYMMDD.log`；含 `trace_id`
- Nginx：`access.log`、`error.log`，格式见 `nginx.conf`
- AI 引擎：`zhixiao-ai` 容器 stdout，`docker logs zhixiao-ai -f`
- 跨服务关联：所有 HTTP 请求都拿同一个 `X-Trace-Id`；服务间通过 SSSE 事件 `data.task_id` 二次关联

### 6.2 健康检查
- `/health` 路径由各容器暴露，默认 30s 检查
- 后端会 ping DB / Redis / Chroma（生产可扩展为聚合 health）

### 6.3 监控 / 告警
- 基础：`deploy/monitor.sh` 做存活探测 + 文件日志
- 进阶：Prometheus + Grafana + Alertmanager（本期预留）
  - 关键指标：服务 QPS、SSE 活跃连接数、任务成功率、Agent 平均耗时、Chroma 检索耗时
- 告警阈值建议：
  - 服务存活异常 > 1 min -> P1
  - 任务失败率 > 15% / 1h -> P2
  - Chroma 检索 P95 > 1s -> P3
  - 磁盘使用 > 80% -> P2

## 七、配置项变更生效一览

| 改 | 操作 |
|----|------|
| 限流阈值 | 改 `.env`，`bash deploy/control.sh restart backend` |
| LLM 厂商切换 | 改 `LLM_PROVIDER/API_BASE`，仅重启 ai |
| Nginx 配置 | 改 `nginx/nginx.conf`，`docker compose restart frontend` |
| 数据库 schema | 新迁移文件 + `docker compose exec backend alembic upgrade head` |
